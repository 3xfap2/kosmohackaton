# Орбита — сервис проектирования устойчивой спутниковой группировки

Решение кейса «Проектирование устойчивой спутниковой группировки», КосмоХакатон 2026.

Инженер-проектировщик выбирает конфигурацию группировки из 48 аппаратов, проверяет её на
отказах и видит, получает ли каждый северный наземный пункт связь со шлюзом и какую долю
времени.

## Быстрый старт

Нужны Node.js 20.19+ (или 22.13+, 24+) и npm.

```bash
npm install
npm run dev        # http://localhost:5173
```

Рабочее место открывается по адресу `/app` и **не требует входа**: сценарий
`01_full_constellation` загружается и считается автоматически.

```bash
npm run build      # сборка в dist/
npm run preview    # проверка собранной версии
npm test           # 118 автотестов
npm run fixtures   # пересобрать эталонные снапшоты (нужны Python 3.10+ и NumPy)
```

Для `npm test` не нужны ни Python, ни файлы кейса: сценарии лежат в `public/scenarios`, а эталонные
снапшоты `geometry.py` — в `tests/fixtures`. Пересобирать снапшоты нужно, только если меняется
эталон: скрипт ищет `geometry.py` в папке `Расчетный модуль` рядом с папкой репозитория.

## Что умеет сервис

**Загрузка своего сценария.** Кнопка «Загрузить файл» или перетаскивание файла в окно.
Принимаются и сценарии `cosmo-A-1.0`, и выгруженные результаты `cosmo-A-result-1.0` — из
результата берётся `effective_scenario`. Некорректный файл не применяется: сервис перечисляет
все ошибки с указанием поля, например `design.satellites[5] (S06).plane_id: ссылка на
неизвестную плоскость "P9"`.

**Правка конфигурации.** Этап развёртывания (16, 32 или все 48 аппаратов), RAAN и фазирование
каждой плоскости, периоды недоступности аппаратов и периоды недоступности шлюза. Кнопка «Сброс»
возвращает сценарий к состоянию после загрузки.

**Локальная маска горизонта.** Каждому наземному пункту можно задать свой порог угла возвышения:
рельеф и застройка вокруг площадки поднимают эффективный горизонт выше общего порога сценария.
Это расширение поверх формата кейса — поле `min_elevation_deg` у наземного пункта
необязательное, и без него расчёт идёт по общему порогу из `environment`.

**Состояние сети в любой момент.** Глобус или карта, таймлайн на все отсчёты суток,
воспроизведение, переход к следующему и предыдущему перерыву. Клик по аппарату открывает его
состояние: плоскость, очередь запуска, число связей, угол возвышения, периоды отказа — и там же
задаётся новый отказ.

**Маршрутизация с разбором причины.** Когда пути нет, называется одна из четырёх причин: нет
видимого спутника, разрыв межспутниковой сети, нет контакта со шлюзом, шлюз недоступен.

**Сравнение вариантов и рекомендация.** Варианты сохраняются целиком и сравниваются по
доступности каждого пункта, средней доступности, длительности перерывов, числу переходов,
задержке и числу смен маршрута. Рекомендация выбирается по средней доступности; при равенстве
решает худший пункт, затем самый длинный перерыв. Если условия расчёта у вариантов различаются,
сервис об этом предупреждает.

**Подбор ориентации плоскостей.** Перебор равномерных схем по шагу RAAN и сдвигу фазы с
тепловой картой результата; клик по ячейке применяет схему.

**Анализ устойчивости.** Зависимость от шлюза (доля перерывов по его вине и окна, когда связь
теряют все пункты сразу), стабильность маршрутов, доля времени с резервным путём, загрузка
аппаратов и поиск самых уязвимых перебором отказов.

**Диагноз проекта.** Одна кнопка сводит все расчёты в письменное заключение: достигнут ли
целевой уровень, где узкое место, какой аппарат критичен, какая схема ориентации плоскостей
лучше и что будет при одновременном отказе десяти самых уязвимых аппаратов. Текст копируется
одной кнопкой — он готов для записки и презентации.

**Выгрузка.** «↓ Сценарий» — правки в формате `cosmo-A-1.0`. «↓ Результат» — формат
`cosmo-A-result-1.0`: полный `effective_scenario`, маршруты по каждой паре «отсчёт — пункт» и
сводные показатели. Оба файла загружаются обратно без потерь.

## Структура проекта

```
src/core/                 расчётная логика, не зависит от интерфейса
  geometry.ts             порт geometry.py: положения аппаратов, видимость, ISL
  routing.ts              поиск маршрута, причина разрыва, резервный путь
  simulate.ts             прогон по сетке времени и показатели
  analysis.ts             рекомендация, зависимость от шлюза, подбор, уязвимые аппараты
  validate.ts             проверка входного файла по «Описанию данных»
  export.ts               выгрузка cosmo-A-result-1.0
  variants.ts             сохранённые варианты проекта
src/routes/               страницы: обзор, рабочее место, методика, профиль
src/components/           глобус, карта, диаграмма доступности, изоляция сбоев
src/components/workspace/ панели рабочего места
tests/                    автотесты, включая сверку с эталоном
tools/make_fixtures.py    снятие эталонных снапшотов с geometry.py
public/scenarios/         четыре сценария кейса
```

Расчётная логика отделена от интерфейса намеренно: любую функцию ядра можно вызвать из теста
или скрипта без React.

## Проверка корректности расчётов

Ядро переписано на TypeScript и **сверяется с приложенным к кейсу `geometry.py` побитово**.
`tools/make_fixtures.py` запускает эталонный модуль на четырёх сценариях в семи моментах времени
и сохраняет полные снапшоты в `tests/fixtures/`. Тест сравнивает с ними координаты аппаратов,
состав активных аппаратов, полный список рёбер и углы возвышения по каждому пункту. Допуск 10⁻⁹.

```bash
npm test
```

## Расчётная модель

**Положение аппаратов.** Круговые орбиты, сферическая Земля, R = 6371 км,
μ = 398600,435507 км³/с². Для высоты h радиус r = R + h, угловая скорость n = √(μ/r³),
аргумент широты u(t) = slot_deg + phase_deg + n·t. Инерциальные координаты поворачиваются в
систему, связанную с Землёй, на угол θ = earth_angle0 + 2πt/T.

**Связи.** Наземная линия доступна при угле возвышения не ниже `min_elevation_deg` и активном
аппарате; для шлюза дополнительно учитывается его доступность. Межспутниковая линия доступна при
расстоянии меньше `isl_range_km`, если отрезок между аппаратами не пересекает Землю.

**Маршрутизация.** Поиск в ширину от всех аппаратов, видимых из наземного пункта, до любого
доступного шлюза. Промежуточные узлы — только спутники: клиентские пункты не ретранслируют
трафик. BFS выбран сознательно: показатель доступности учитывает наличие пути, а не его длину, а
минимальное число переходов совпадает с инженерным предпочтением коротких цепочек.

**Причина отсутствия маршрута** определяется послойно: есть ли видимый аппарат → достижим ли по
межспутниковой сети сегмент со шлюзом → есть ли у шлюза контакт → доступен ли сам шлюз.

**Показатели.** Доли — отношение числа отсчётов к их общему числу. Максимальный перерыв — самая
длинная непрерывная цепочка отсчётов без маршрута, умноженная на `step_s`; перерывы на границах
периода учитываются отдельно. Число переходов включает обе наземные линии. Задержка — время
распространения сигнала в одну сторону по прямым отрезкам маршрута, без обработки на борту.
Резервный путь — маршрут, не использующий ни одного спутника основного.

## Профиль проектировщика

**Без входа доступно всё, что оценивается:** расчёт, загрузка своего сценария, правка
конфигурации, выгрузка результата, анализ устойчивости, а также сравнение трёх эталонных
вариантов кейса — полной группировки, первой очереди и сценария отказов — с автоматической
рекомендацией.

**Профиль нужен, чтобы сохранять собственные варианты.** Хранилище **локальное**: учётные
записи и варианты лежат в `localStorage` браузера, сервера у решения нет, данные никуда не
передаются. Это не средство защиты доступа, и выдавать его за таковое мы не будем. Профиль
создаётся мгновенно, без подтверждения почты.

## Развёртывание

Решение — статическое приложение без бэкенда: весь расчёт идёт в браузере, полный прогон суток
занимает десятки миллисекунд. Подходит любой статический хостинг.

```bash
npm run build
# содержимое dist/ выкладывается на хостинг
```

Для маршрутов вида `/app` нужен SPA-фолбэк — конфигурации уже в репозитории: `vercel.json` для
Vercel и `public/_redirects` для Netlify.

## Источники данных

Сценарии в `public/scenarios/` — копии файлов, предоставленных организаторами кейса. Контуры
материков на глобусе — пакет `world-atlas` (Natural Earth, 1:110m, public domain). Числовые
параметры кейса синтетические.
